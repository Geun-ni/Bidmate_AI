# 적격심사 서류 조건 — 공고문, 적격심사기준 원문 위치 검증 
## 요약

- 확보·읽기: 23건 × 2문서 = 46문서 모두 최종 확보·읽기 성공
 확보 경로는 공고문 Open API 11 / SRM 보완 12, 적격심사기준 Open API 6 / SRM 보완 17 (6건은 Open API 조회 기간 90일 밖). 
- 오류 2건: E012606980 API 링크가 파일 대신 HTML 반환, E012607149 안내문을 공고문으로 오분류) — 둘 다 SRM에서 실제 파일을 받아 해결.
- 항목 위치: 23건 × 9항목 = 207개 중 찾음 156, 해당 없음이 확인됨 15, 문서에서 찾지 못함 36.
  - "문서에서 찾지 못함"은 실제로 해당 문서에 내용이 없는 경우임
- 주요 발견
  1. SRM `overHeadCostAmount`는 순공사원가가 아니라 '경비'임.
  순공사원가(재료비+노무비+경비)는 공고문에 별도로 존재함
    - 순공사원가는 `bid_notice.net_construction_cost`에 저장중임
  2. A금액은 SRM 값과 원문 값이 공사 15건 모두 같다.
  3. 표 구조가 사라진다. 배점 기준표, 사업소 점수표, 경영상태 등급표, 진단·PQ의 입찰가격 산식(표 칸 안), 공고문 금액표는 현재 파서에서 칸이 한 줄씩 흩어져 값의 소속(어느 행·열)을 알 수 없다.
  4. 유형마다 같은 항목의 위치·형식이 다르다 (아래 3장). 특히 진단용역은 입찰가격 산식이 배점표 칸 안에 글자로 들어 있고, 감리 PQ는 한 칸에 수행능력 환산식과 입찰가격 산식이 함께 있다.

## 2. 항목 위치와 원문 발췌

- 위치 표기: 적격심사기준은 `[별표 N] > 제N조 > 주N)`, 공고문은 번호 항목(`3. 입찰참가자격 …`). 표 안에서 찾은 경우 `표 N행` 또는 `표 칸 안 (N행 M열)`. HWP는 쪽(페이지) 정보가 파일에 없어 쪽은 확인 불가.
- 상태 구분: `찾음` / `문서에서 찾지 못함`/ `해당 없음`(원문에 '해당사항 없음'이 명시되어 있는 경우) / `파일 미확보나 읽기 실패로 확인 불가`
- 입찰참가자격 증명 서류: "적격심사대상자의 입찰참가자격은 아래와 같이 확인" 같은 적격심사 단계 확인 방법을 먼저 찾고, 없으면 입찰참가신청 시 제출서류(대부분 "제출서류 : 해당사항 없음")를 기록함. 따라서 `해당 없음이 확인됨`은 입찰참가신청 단계에서 낼 서류가 없다는 뜻.
- A금액·순공사원가: `원문`(공고문에서 직접 찾은 값)과 `SRM 수집값`(웹 상세 `totalAAmt`, `overHeadCostAmount`)을 구분했다. SRM 값이 원문 어디와 같은지도 표시해둠
- 원문의 분수 막대(한글 전용 문자)는 `─`로 바꿔 표시했다.

### 3.2 유형 안에서 양식이 다른 점

- **감리:** 고시금액 미만(`[별표 10]`, 수식 개체 3개)과 PQ(`[별표 14]`, 수행능력 70·입찰가격 30, 수식 개체 0개)는 기준서 자체가 다르다. PQ는 배점표 한 칸(2행 3열)에 수행능력 환산식 `* 평점 = ─ × 70점`과 입찰가격 산식이 함께 들어 있다.
- **진단:** 4건 모두 산식이 배점표 칸 안 글자 3줄이다. 첫 줄 숫자 표기가 `88 입찰가격`(E012604208, E012603958)과 `90 입찰가격`(E012606484, E012608116)으로 공고마다 다르다. 수식 개체는 실적 비율용 1개뿐이다.
- **배전 총액:** 같은 양식이지만 `[별표 1]` 제목에 금액 구간이 붙은 문서(E012605917)와 없는 문서가 있다. 사업소 점수표 배점이 2점(1.6~3억)과 4점(3억 이상)으로 다르다.
- **변전·지중송전:** 같은 유형에서도 산식 제목이 `주2)`/`주3)`, "평가산식"/"평가계산식"으로 다르다.
- **송전:** 기준서 수식 개체 수가 4~18개로 차이가 크다(E012607077 18개).
- **공고문 금액 표기:** 같은 유형에서도 A금액이 금액표 행으로 나오는 경우와 본문 `A = …` 문장으로 나오는 경우가 섞여 있다.

## 4. 제안 (적용하지 않음 — 팀 확인 후 진행)

### 4.1 표 파서 개선
- **필요한 항목:** 배점 기준표, 해당·인접 사업소 점수표, 경영상태 등급표(배전·진단), 진단·감리 PQ 입찰가격 산식(표 칸 안), 공고문 금액표(A금액·순공사원가 행 이름과 금액의 짝).
- **근거:** 3.3 — 현재 파서는 칸을 한 줄씩 흩어 놓아 값의 행·열 소속을 알 수 없다. 이번 검증용 표 해석기(HWP: `LIST_HEADER`의 열·행 주소, HWPX: `hp:tc/hp:cellAddr`)로 46문서의 표를 모두 복원할 수 있었다.
- **방법(안):** `doc_reader`가 문단과 함께 표 블록(행·열·칸 텍스트)을 돌려주게 하고, `bid_document_content`에 `tables` JSON 컬럼을 추가한다(`init_db.COLUMN_MIGRATIONS`에 등록). AI 파트가 표를 행·열 그대로 받을 수 있다.

### 4.2 DB 테이블 추가
- **`document_item_location`(안):** `bid_attachment_id`, `item`, `status`, `location`, `format`, `excerpt`, `found_by`(=RULE).
- **필요한 이유:** 이번 결과는 보고서·JSON에만 있다. DB에 두면 ① AI 파트가 원문 전체 대신 해당 부분만 LLM에 넘길 수 있고, ② 화면에서 "원문 위치"를 보여줄 수 있다. 규칙 기반 결과라 LLM 추출값(`document_extraction`)과는 따로 둔다.

### 4.3 수집기 수정이 필요한 점 (이번 검증에서 발견)

> 1~3은 2026-11-20 수정함 → [2026-11-20_경비정정_문서수집오류_수정.md](2026-11-20_경비정정_문서수집오류_수정.md). 순공사원가를 공고문 금액표에서 채우는 부분은 표 파서 통합과 함께 팀 결정으로 남김.

1. **`overHeadCostAmount` = 경비:** 공사 15건 모두 경비와 일치했다. `bid_notice.net_construction_cost`(순공사원가)라는 이름이 틀렸다. `overhead_cost_amount`(경비)로 바꾸고, 순공사원가는 공고문 금액표에서 가져오는 방안. 기획(영래) 데이터 정의 확인 필요.
2. **공고문 오분류:** 파일명에 '공고문'만 있으면 공고문으로 본다. '안내' 등 제외 규칙이나 '입찰공고문' 우선 규칙이 필요하다(E012607149).
3. **API 링크가 HTML을 줄 때:** 수집기는 다운로드가 되면 확보로 보고 SRM 보완을 하지 않는다. 파일 시그니처를 확인해 실패로 처리하고 SRM에서 보완해야 한다(E012606980).
4. **공고문이 여러 개일 때(원본+정정):** 정정본을 우선 고르는 규칙이 필요하다.

### 4.4 팀이 정할 것
- 용역(감리·진단)은 A금액·순공사원가가 원문에 없고 SRM 값도 0이다. 화면에서 '해당 없음'으로 보여줄지.
- 해당·인접 사업소 항목은 대표 공고 중 배전 총액에만 있다. 다른 유형에서는 이 항목을 숨길지.
