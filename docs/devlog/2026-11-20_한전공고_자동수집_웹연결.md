# 2026-11-20 한전 공고 매일 자동 수집 + 웹 화면 연결

범위: 수집 → SQLite 저장 → 웹 API 조회 → 화면 표시. 메일·텔레그램 알림은 다음 단계(감지 지점만 문서화).

## 1. 매일 12:00 자동 수집

- 방식: 운영 PC(Windows 11, 시간대 Korea Standard Time)의 **작업 스케줄러**. DB가 이 PC의 로컬 SQLite라서 GitHub Actions 같은 외부 예약은 쓰지 않았다.
- 등록: `scripts/register_daily_collect.ps1` → 작업 `BidmateDailyCollect`, 매일 12:00, 실행 `scripts/collect_daily.ps1` → `python -m backend.collector.collect --days 7 --limit 5`. **실제 등록됨**(다음 실행 2026-11-21 12:00).
- 주의: 로그인돼 있을 때만 실행. 꺼져 있었으면 켜진 뒤 한 번 실행. 노트북 배터리에서도 실행되게 설정했다(기본값은 배터리면 `Queued`로 멈춤 — 처음 등록 때 실제로 걸렸음).
- 수집 규칙은 기존 그대로: 공식 API 최근 7일, 한전 공사·용역 적격심사, 이미 상세 수집한 공고 건너뜀, 정정 공고 우선 재수집, 실패·부분 수집은 다음 실행에서 재시도, 상세 수집 한도 5건.
- 실행 결과 건수: `collect_run`에 `new_notice_count`, `completed_count`, `deferred_count`(한도로 남은 건), `failed_count` 추가(기존 DB는 `init_db` 마이그레이션으로 추가). 로그 `logs/collect_YYYYMMDD.log`, 화면 상단에도 표시.
- 수집기 변경: 공고 1건에서 예상 못 한 오류가 나도 실행 전체를 멈추지 않고 실패로 세고 다음 공고로 넘어감(SRM 차단 의심은 기존처럼 중단).

## 2. 웹 화면

- API: `backend/notices_api.py`(읽기 전용) + `backend/server.py`
  - `GET /api/notices` — 진행 중 공고(`?include_closed=1`이면 마감 포함) + 마지막 수집 결과
  - `GET /api/notices/<공고번호>` — 기본정보 + 면허·적격자격 조건 + SRM 상세(A금액·경비·개찰)
  - `/api/demo`는 남겨 뒀지만 기본 화면은 쓰지 않음
- DB 경로: 수집기·서버·예약 실행 모두 `backend/db/init_db.py`의 `resolve_db_path()` 사용. 기본 저장소 루트 `bidmate.sqlite3`(실행 위치 무관), `BIDMATE_DB` 환경 변수나 `.env`로 변경 가능.
- 화면(`frontend/`): 제목 **한전 입찰 공고**. 목록은 공고명·공고번호·신청 기간·투찰 기간·추정가격, 값이 없으면 `미확인`. 공식 API 기본정보만 있는 공고도 목록에 나오고 `SRM 미수집` 표시. 면허·적격자격은 SRM 조회 성공 시 값 또는 `제한 없음`, 조회 전·실패는 `확인 필요`.
