# UI 벤치마크 사이트 목록

> 작성일: 2026-11-19 · 작성: 디자인·프론트
> 목적: React 화면 설계 전 참고할 서비스를 모으고, [기능명세서](../planning/기능명세서.md)의 화면(UI-01~07)별로 무엇을 참고할지 정리한다.
> 기능 설명은 대부분 각 업체의 소개 자료 기준이다. 실제 화면은 직접 열어 보고 캡처해서 확인한다.

## 회의록에서 나온 UI 요구사항

출처: [11-11 아이디어 선정 회의](../meetings/2026-11-11_아이디어-선정-회의.md), [11-18 회의록](../meetings/2026-11-18%20입찰메이트_회의록.md). 벤치마크는 아래 기준으로 본다.

| 회의 내용 | 화면에 필요한 것 |
| --- | --- |
| 주 사용자는 **입찰 경험이 적은 소규모 업체** (11-11) | 용어 설명, 입찰 절차(참가신청 → 투찰 → 개찰 → 적격심사 → 계약) 안내, 초보자도 읽히는 정보 위계 |
| 팀은 **SRM 운영 기관 입장**에서 기획 (11-11) | 공공 서비스다운 신뢰감 있는 톤 (KRDS 참고) |
| 추천은 **최종 자격 충족으로 단정하지 않음**. 자동심사 조건과 서류로 확인할 조건을 구분 (11-18 §2.2) | 조건별 판정 상태(자동 확인 / 확인 필요 / 서류 확인) 배지, 판정 근처 면책 문구 |
| 수동심사 항목은 **별도 확인 필요 표시** (11-18 §2.3) | "입찰참가자격 확인 필요" 배지와 사유 |
| 공식 API 첨부파일이 최대 5개라 **공고문·적격심사기준이 누락**될 수 있음 (11-18 §2.1) | 공고별 "문서 확보 상태" 표시, 문서가 없을 때 요약·점수·서류 탭의 빈 상태 화면 |
| 점수 계산 **1안 확정**: 사용자는 입찰가격·예정가격 2개만 입력, A값은 공고문에서 자동 추출 (11-18 §2.5) | 입력 2칸 + 자동 추출 값(출처 표시) + 결과. A값이 없으면 "계산 보류, 원문 확인 필요" 상태 |
| **투찰가격 추천은 범위 제외** (11-18 §2.5) | 추천 가격처럼 보이는 UI는 만들지 않는다 |
| 예상 점수는 **낙찰을 보장하지 않음** (11-11) | 점수 결과 옆에 참고용 안내 |
| 메인에 **업체정보 · 관심공고 달력 · 추천 공고 목록** 배치 제안 (11-18 §2.3) | UI-01 레이아웃 |
| 관심공고 등록·필터 (11-18 §2.3) | 별표 토글, "관심공고만 보기" |
| 면허·자격·지역은 **코드 목록에서 검색·선택** (11-18 §2.3) | 검색형 다중 선택, 광역 → 시군구 종속 선택 |
| 신규 공고 **이메일·텔레그램 알림**, 채널·시점 미정 (11-18 §2.6) | UI-07은 후순위. 이메일 입력란만 업체정보에 자리 확보 |

## 우선순위 요약

사용자가 대기업 입찰팀이 아니라 **소규모·초보 업체**이므로, 엔터프라이즈 도구(GovWin IQ, GovSpend)보다 쉽고 안내가 친절한 서비스를 우선 참고한다.

| 순위 | 서비스 | 이유 |
| --- | --- | --- |
| ★★★ | Instrumentl | 매칭 → 관심 저장 → 마감 트래커 → 달력 흐름이 입찰메이트와 거의 같다 |
| ★★★ | Stotles | 공공 조달 SaaS 중 시각 완성도가 높고, 공고 알림·필터 설계가 명확하다 |
| ★★★ | Tendium | 긴 공고문을 요구사항·마감 중심으로 요약한다 (요약 탭 참고) |
| ★★★ | 인포21C | 국내 대표 입찰정보 서비스. 사용자가 익숙한 용어와 정보 구조 |
| ★★ | HigherGov, Sweetspot | 데이터 밀도가 높은 목록과 모던 AI 검색 UI |
| ★★ | 사람인·자소설닷컴 채용달력 | 마감 D-day, 스크랩, 일정 달력 패턴 |
| ★★ | KRDS | SRM 운영 기관 입장의 공공 서비스 톤과 접근성 기준 |
| ★★ | 웰로 | 국내 초보 사용자 대상 맞춤 추천 화면 |
| ★ | GovWin IQ, GovSpend | 대기업 입찰팀용이라 우선순위 낮음. 데이터 표현만 참고 |
