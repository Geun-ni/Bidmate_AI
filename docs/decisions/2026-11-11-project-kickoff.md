# 입찰메이트 주제 및 협업 방식 결정

- 일정은 2026년 11월 11일(수)부터 11월 12일(목)까지다.
- 담당은 팀원 전원이다.

## 프로젝트 주제와 첫 데모 범위

입찰메이트는 업체의 면허·지역·희망 금액대에 맞는 공공 입찰 공고를 추천하고, 공고의 핵심 조건과 제출서류를 확인할 수 있게 돕는 서비스다.

첫 데모는 맞춤 공고 추천과 추천 사유, 공고 요약, 제출서류 체크리스트를 우선한다. 공고를 추천할 때는 면허·지역·금액 조건을 규칙으로 비교한다. AI는 공고와 첨부 문서의 내용 추출, 요약, 추천 사유 설명을 맡고, 최종 지원 여부는 사용자가 결정한다. 데모에는 가상 공고와 업체 데이터를 사용한다.

## 역할과 첫 작업 브랜치

| 역할 | 첫 작업 | 브랜치 |
| --- | --- | --- |
| 기획 | 입찰참가자격과 공고 매칭 규칙 정리 | `docs/matching-rules` |
| 디자인·프론트 | 공고 목록과 상세 화면 설계·구현 | `feat/notice-dashboard` |
| 백엔드·데이터 | 공고 데이터 구조, 매칭 규칙 및 API 개발 | `feat/notice-api` |
| AI | 첨부 PDF에서 조건·일정·제출서류를 추출하는 기능 개발 | `feat/pdf-extraction` |

## 브랜치 운영 규칙

1. `main`을 공용 브랜치로 사용한다. 각자 작업 브랜치로 전환하고 현재 브랜치를 확인한 뒤 작업한다.
2. AI 에이전트를 사용하기 전에 진행 중인 작업을 작업 브랜치에 커밋하고 푸시한다. 에이전트에는 수정 범위를 지정하고, 작업 후 변경 파일과 삭제 내역을 확인한다.
3. 작업을 마치면 `main`을 대상으로 PR을 열고 다른 팀원 한 명 이상의 리뷰를 받은 뒤 병합한다. 다음 작업 브랜치는 최신 `main`에서 만든다.

## 진행 결과

- 가상 데이터로 실행되는 개발 뼈대를 GitHub의 `main`에 올렸다.
- 같은 커밋에서 기획, 디자인·프론트, 백엔드·데이터, AI의 첫 작업 브랜치 네 개를 생성했다.
- GitHub에서 PR 리뷰를 강제하고 `main`의 강제 푸시·삭제를 막는 브랜치 보호 설정은 적용 여부를 확인해야 한다.
