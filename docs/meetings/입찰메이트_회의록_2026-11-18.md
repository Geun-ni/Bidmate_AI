# 입찰메이트(Bidmate_AI) 팀 프로젝트 회의록

- **회의일자:** 2026년 11월 18일(수)
- **회의방식:** 카카오톡 단체 대화
- **참여자:** 곽영래, 조용희, 이정근, 강보라
- **회의주제:** 한전 SRM 데이터 수집 방식 및 입찰메이트 주요 기능 구현 방향

## 1. 회의 목적

한국전력공사 SRM 입찰공고 데이터를 활용한 공고 추천 및 적격심사 분석 서비스의 데이터 수집 문제를 검토하고 주요 기능과 개발 방향을 구체화한다.

## 2. 주요 논의 내용

### 2.1. 한전 Open API 첨부파일 제공 제한

**현황 및 문제점**

- 공식 Open API 응답에는 첨부파일이 최대 5개까지 표시되는 것으로 확인됨.
- 실제 공고에 첨부파일이 더 많을 경우, 필수 파일인 **공고문** 또는 **적격심사기준**이 누락되는 사례가 있음.
- 반환되는 5개 파일의 선택 기준은 확인되지 않았으며, 파일명 오름차순이나 파일 크기순과도 일치하지 않는 사례가 있음.
- 필수 파일 누락 시 적격심사 점수 계산과 필요서류 분석이 제한됨.

**논의한 대안**

1. 공식 API에서 필수 파일 두 개를 모두 제공하는 공고만 분석
2. 공식 API를 우선 사용하고 누락된 파일은 SRM 웹 요청으로 추가 수집
3. 데이터 확보가 어려울 경우 1회성 시연 방식 검토

**논의 결과**

- **공식 API 우선 사용 + 필수 파일 누락 시 SRM 추가 조회** 방향으로 의견을 모음.
- 지속 운영을 고려하여 SRM 웹 요청 방식의 안정성 및 유지보수 문제를 검토해야 함.
- 공식 API에서 필수 파일을 확보할 수 있는 비율과 누락 원인 확인이 필요함.
- 이정근이 공식 API 및 첨부파일 조회 방식을 추가 테스트하기로 함.

### 2.2. 입찰참가자격 데이터 수집 및 공고 추천

- 공고 추천을 위해 업체의 입찰참가 가능 여부를 판단할 데이터가 필요함.
- SRM 투찰제한 정보에는 면허, 제한경쟁입찰자격, 지역 등 자동심사 항목이 있으며, 관련 코드는 정형화되어 있음.
- 현재 확인한 공식 API 응답에는 해당 코드가 포함되지 않지만, SRM 웹 화면의 네트워크 응답에서 확인 가능함.
- 공고문에도 입찰참가자격이 기재되지만 공사·용역별 조건이 다양하여 정형화된 규칙만으로 추출하기 어려움.

**논의 결과**

- SRM에서 자동심사 조건을 수집해 업체정보와 비교하여 **맞춤형 공고 추천 목록**을 구성함.
- 공고문에 기재된 추가 자격조건은 별도로 분석함.
- 자동심사 조건과 추후 서류로 확인하는 조건을 구분하고, 추천 결과를 최종 자격 충족으로 단정하지 않음.

### 2.3. 주요 기능 및 화면 구성

**① 업체정보 등록 및 관리**

- 업체 기본정보, 보유 면허, 제한경쟁입찰자격, 지역정보 입력
- 면허·제한경쟁입찰자격·지역은 코드 목록에서 검색 또는 선택
- 업체정보 데이터 정의서와 코드 목록을 기반으로 구현

**② 맞춤형 입찰공고 추천**

- 업체정보와 공고의 투찰제한 조건 비교
- 자동 판정이 어려운 수동심사 항목은 별도 확인 필요 표시
- 관심공고 등록 및 필터 기능 제공

**③ 공고 상세 분석**

- **입찰참가자격 및 적격심사 기준 요약:** 공고문과 적격심사기준 분석
- **적격심사 점수 간편 계산:** 공사수행능력 체크리스트, 입찰가격 계산, 가점·감점 항목
- **필요서류 체크리스트:** 공고문 및 적격심사기준에서 제출서류 추출

**④ 관심공고 및 일정 관리**

- 관심공고의 입찰참가 일정을 달력에 표시
- 메인 화면에 업체정보, 관심공고 달력, 추천 공고 목록 배치 제안

### 2.4. LLM 활용 범위

- 정형화된 코드 비교 외에 생성형 AI의 역할을 분명히 해야 한다는 의견이 제기됨.
- 공고별로 표현과 조건이 달라지는 비정형 문서 분석에 LLM을 활용하는 방향으로 논의함.

**주요 적용 기능**

- 공고문에서 입찰참가자격 및 추가 조건 추출
- 적격심사기준에서 평가항목과 제출서류 분석
- 제출서류 요약 및 체크리스트 생성
- SRM 투찰제한 정보와 공고문 분석 결과 비교·검토
- **GPT API를 활용해 업체 조건에 부합하는 신규 입찰공고를 선별·요약하고, Gmail을 통해 맞춤형 공고 안내 메일 발송**

### 2.5. 적격심사 점수 계산

**검증 및 결정 사항**

- **HWP/HWPX 문서 내 입찰가격 평가산식 인식은 검증 완료된 것으로 정리함.**
- 입찰가격 점수 계산은 기존 검토안 중 **1안(평가산식 기반 자동 계산)**으로 확정함.
- 사용자가 직접 입력하는 값은 **입찰가격**과 **예정가격** 두 가지임.
- 산식에 필요한 **A값은 해당 공고문에서 자동 추출**하여 사용하며, 사용자가 별도로 입력하지 않음.
- 시스템은 해당 공고의 적격심사기준에서 확인한 평가산식에 **입찰가격·예정가격·A값**을 적용하여 입찰가격 점수를 자동 계산하고 결과를 표시함.
- 공고별 평가산식과 적용 조건을 반영하며, A값을 추출하지 못한 경우에는 임의의 값을 넣어 계산하지 않고 확인이 필요함을 안내함.
- 공사수행능력과 가점·감점 항목은 체크리스트 형태로 제공함.
- **투찰가격 추천 기능**과 **입찰가격 점수 계산 기능**은 구분하며, 투찰가격 자체를 추천하는 기능은 우선 구현 범위에서 제외함.

**계산 흐름**

1. 공고문에서 해당 공고의 **A값** 자동 추출
2. 적격심사기준에서 해당 공고의 **입찰가격 평가산식** 확인
3. 사용자에게 **입찰가격·예정가격** 입력받기
4. 세 값을 평가산식에 대입하여 **입찰가격 점수 자동 계산 및 표시**

### 2.6. 맞춤 공고 알림

- 업체 조건에 부합하는 신규 공고를 이메일 또는 텔레그램으로 알리는 기능 제안
- 업체정보 등록 시 이메일 주소 입력 방안 논의
- 신규 공고 등록 시 문서를 한 번 조회·분석해 저장하고 재사용하는 방안 논의
- 알림 기능 추가 방향에 긍정적인 의견을 모았으며, 채널과 발송 방식은 추후 결정

### 2.7. GitHub 협업 및 자료 공유

- `docs/matching-rules` 브랜치에 기능명세서, 업체정보 데이터 정의서, SRM 첨부파일 수집 PoC 작성
- `main` 대상 **PR #10** 생성 및 공유
- 면허종류, 지역제한 목록, 제한경쟁입찰자격 종류를 정리한 엑셀 파일 공유
- 작업 시 `git fetch` 등으로 최신 변경사항 확인 필요
- 논의 내용을 반영해 기능명세서를 수정하기로 함

## 5. 미해결 과제

1. 공식 API가 반환하는 5개 첨부파일의 선택 기준 및 필수 파일 확보율 확인
2. SRM 내부 요청 방식의 안정성, 이용정책 및 접근 권한 확인
3. 자동심사 코드와 공고문 조건이 불일치하거나 누락된 경우의 처리 방식
4. LLM의 입찰참가자격 및 제출서류 추출 정확도 검증
5. 이메일·텔레그램 알림 중 우선 채널과 발송 시점 결정
6. 가상 업체정보를 이용한 실제 공고 매칭 테스트 검토

## 6. 최종 정리

입찰메이트는 **업체정보 기반 맞춤형 입찰공고 추천**과 **공고문·적격심사기준을 활용한 AI 분석**을 핵심 기능으로 개발한다. 공고 데이터는 한전 공식 Open API를 우선 활용하고, 필수 첨부파일이나 입찰참가자격 정보가 부족하면 SRM 추가 조회를 검토한다.

LLM은 비정형 문서의 자격조건·제출서류 추출과 요약에 중점적으로 적용하며, 맞춤형 신규 공고 알림 기능도 추진한다.

**우선 과제:** 데이터 수집 안정성 검증, 공고 추천 자격조건 매칭 구현, 기능명세서 업데이트.

---

> **보안 유의:** 카카오톡 대화에 노출된 API 키는 회의록에 포함하지 않았음. 키 재발급 및 환경변수 관리 권장. 외부 공유가 제한된 자료는 승인된 범위에서만 사용.
