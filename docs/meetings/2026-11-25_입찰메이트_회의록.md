# 입찰메이트(Bidmate_AI) 회의록 — 2026.11.25

## 1. 회의 개요

- 일시: 2026년 11월 25일
- 참여자: 강보라, 곽영래, 이정근, 조용희
- 목적: Open API 장애 대응, 공고 수집·추출 파이프라인 점검, 실무자 관점의 프론트엔드 개선, AI 및 베타 테스트 후속 작업 정리

## 2. 주요 논의 및 결정 사항

### 2.1 한전 Open API 장애 및 수집 대응

- 한전 전력데이터 포털의 Open API 테스트 페이지에 접속할 수 없어 공고 수집에 차질이 발생했다.
- 곽영래가 담당자에게 문의한 뒤 월요일까지 접속이 제한될 예정이라고 공유했다. 장애의 정확한 원인은 확인되지 않았다.
- Open API 장애에 대비해 접속 가능한 SRM 목록을 이용하는 대체 수집 경로를 마련했다.
- Open API가 복구되면 자동수집 예약을 설정하고 정상 수집 여부를 확인한다.
- SRM 목록으로 수집한 일부 공고는 DB의 발주부서(`place_name`) 값이 비어 있어 화면에 ‘한국전력공사’만 표시될 수 있음을 공유했다.

### 2.2 공고 추천·검색·필터 개선

- 기본 추천은 업체의 자격과 지역 제한 조건을 충족하는 공고를 보여주되, 지역 제한이 없는 전국 공고도 포함한다.
- 사용자가 원할 때 지역, 면허, 공사/용역, 금액 구간 등으로 범위를 좁힐 수 있도록 한다. 업체 주소는 본점 소재지 1개를 기준으로 한다.
- 공고 정렬에 금액 낮은 순을 추가하고, 검색 대상에 발주부서를 포함한다.
- 필터가 많아진 점을 고려해 상세 필터를 접고 펼치는 구조로 정리한다.
- ‘조건불일치 포함’과 동작이 혼동되는 ‘필터 풀기’ 버튼은 제거하는 방향으로 논의했다.
- 공사/용역 구분과 세부 공사유형(`work_type`) 분류는 구별한다. 세부 공사유형은 동일한 적격심사기준을 사용해도 참가자격이 다를 수 있어 단일 기준으로 확정하기 어렵다.

### 2.3 관심공고 달력 및 공고 상세

- 관심공고를 중심으로 일정을 표시한다. 주요 일정은 참가신청 마감, 투찰 마감, 개찰의 3단계로 정리한다.
- 적격심사 서류 제출처럼 공고별로 기한을 직접 관리해야 하는 경우를 위해 달력에 일정을 수기로 추가하는 기능을 둔다.
- 외부 캘린더 일괄 연동은 인증·보안 및 사용 절차에 대한 우려로 이번 작업에서 추진하지 않기로 했다.
- 공고 상세에서는 주요 단계의 남은 시간과 원본 공고문 등 파일 접근성을 개선한다.

### 2.4 AI 질의응답 및 추출 파이프라인

- 기존 SRM 챗봇과의 차별점으로, 일반적인 입찰 원칙뿐 아니라 **특정 공고의 조건·일정·배점·서류에 관해 답변하는 기능**을 지향한다.
- 조용희가 채팅 RAG/LLM 연동을 진행한다. 현재 프론트엔드의 자동 답변은 화면 데이터를 활용하는 대체 동작이며, 실제 백엔드 AI 연동 완료를 의미하지 않는다.
- 평가산식·제출서류 추출은 룰 결과를 우선 보존하고, 필요한 항목을 LLM으로 보완하는 흐름을 정리했다. LLM 보완 결과는 원문 근거와 첨부 버전을 확인해 `REVIEW` 상태로 저장한다.
- 산식 LLM 보완은 수집 종료 후 대상 1건을 처리하도록 제한하는 변경이 추가됐다. 실제 공고·유료 API 실행 및 추출 정확도 검증은 후속 과제다.

### 2.5 베타 테스트·문서화·협업

- 기능이 어느 정도 완성되면 계약 업무 실무자에게 사용을 요청하고 약 1주일간 의견을 수집하는 방안을 논의했다. 구체적인 시작일은 정하지 않았다.
- 만족도 및 개선 의견을 받을 수 있도록 프론트엔드 UI와 백엔드 저장 API를 연결한다.
- 발표자료 대신 README를 작성하라는 안내를 공유했으며, 사용자 매뉴얼과 서비스의 AS-IS → TO-BE를 보여주는 소개 화면도 필요하다는 의견이 나왔다.
- 수정 요청은 GitHub Issues로 등록하고 담당자를 지정한다. 각자 완료한 업무는 프로젝트 칸반보드에서도 완료 처리한다.
