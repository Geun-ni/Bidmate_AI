## 1\. 아이디어 검토

### 1-1. 네트워크 자산 관리 시스템 (강보라)

* **배경**: 사업장·관리 업체별로 네트워크 장비와 유휴자산을 엑셀로 나누어 관리하고 있어, 전체 현황 파악과 유휴자산 재활용이 어렵다.
* **주요 기능**: 자산 현황 대시보드, 장비 모델 정보(백과사전) 검색, 유휴자산·GBIC 재고 관리
* **AI 활용**: 자연어 기반 장비 검색, 요구 조건에 맞는 장비 추천, 대화형 재고 조회
* **검토 의견**

  * 데이터만 확보되면 구현은 수월하나, 핵심 기능 대부분이 AI 없이도 구현 가능하여 AI 활용의 필요성이 상대적으로 약하다.
  * 사내 실데이터를 사용할 수 없어 자산 데이터는 가상 데이터로 시연해야 한다.

### 1-2. 설비 Setup 작업 안전감시 AI (조용희)

* **배경**: 신규 설비 Setup 작업이 늘면서 안전감시 인력 부담이 커지고, 감시자에 따라 품질 편차가 발생한다.
* **주요 기능**: 영상 객체 인식(YOLO·CNN)으로 위험 행동 감지 → 관제 담당자에게 알림 → 출동·원격 조치
* **감지 대상**: 작업 중단 여부, 쓰러짐 등 인명 사고, 위험구역 진입
* **진행 현황**: 모바일 앱으로 "작업자가 일정 시간 쓰러져 있으면 메신저 알림"까지 시험 구현
* **검토 의견**

  * 전 과정을 구현해 시각적으로 시연하기 좋고, 현업 AX 사례로 제시할 수 있다.
  * 실제 적용을 위해서는 위험 상황의 정의와 감지 정확도(정탐률) 검증이 필요하다.

### 1-3. ChangeLens — 변경 영향 분석 도구 (이정근)

* **배경**: 요구사항 하나가 바뀌어도 DB 스키마·API·화면을 모두 검토해야 하며, 누락 시 다른 기능에 오류가 발생한다.
* **주요 기능**: 변경 요청을 입력하면 AI가 전체 구조를 분석해 수정 대상 파일·기능, 추천 코드, 예상 위험 요소를 제시
* **차별점**: 일반 코딩 도구와 달리 DB·API·UI 세 계층의 연관 관계를 정확하게 연결하는 데 초점
* **확장 방향**: 서비스 영향 범위 분석, 테스트 자동화, API 명세·사용 설명서 자동 갱신
* **검토 의견**: 실제 개발 경험에서 도출된 문제로 공감도가 높고 확장 방향이 명확하다.

### 1-4. SRM 입찰 도우미 서비스 (곽영래) — 선정

* **배경**

  * 한전과 전력그룹사는 조달청 나라장터가 아닌 자체 전자입찰 시스템(SRM)으로 공고한다.
  * 적격심사 기준과 제출 서류가 공사 종류·금액대별로 달라, 입찰 경험이 적은 소규모 업체가 어려움을 겪는다.
* **데이터**: 전력데이터 개방 포털 OPEN API(전자입찰·계약 정보), 공고 첨부파일(HWPX·PDF)
* **주요 기능**

  1. 업체 정보 등록 (면허, 소재지, 경영 상황 등)
  2. 업체 정보와 입찰참가자격을 비교해 참여 가능한 공고 추천
  3. 공고 첨부파일 분석: 참가 자격·심사 항목·배점·제출 서류 요약
  4. 적격심사 예상 점수와 부족 항목 안내, 가격 점수 만점 구간 제시 (낙찰을 보장하지 않음을 명시)
* **기대 효과**: 업체의 입찰 준비 부담 감소, 운영 기관의 안내·문의 업무 감소
* **논의 내용**

  * **AI의 역할 범위**: 적격심사 판정은 오판 시 업체에 불이익이 생기므로 규칙 기반으로 처리한다. 심사 항목과 배점이 정해져 있어 자동화가 가능하다. 다만 기준이 다양하므로 확정 판정이 아닌 "예상 점수"로 제공한다.
  * **데이터 수집 방식**: 공식 OPEN API가 제공되므로 크롤링보다 API를 사용한다. 공공데이터로 신뢰성도 확보된다.
  * **첨부파일 분석**: 자동 분석이 어려운 경우를 대비해, 공개 공고의 첨부파일을 예시 데이터로 확보한다.
  * **업무 관련성**: 외부 업체 대상 서비스이므로, 팀이 SRM 운영 기관이라는 전제로 기획한다.
* **검토 의견**: 공개 API로 데이터 확보가 가능해 구현 가능성이 높고, 문서 분석·요약·매칭에 생성형 AI를 자연스럽게 적용할 수 있다.
