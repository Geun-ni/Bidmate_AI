# 입찰메이트 회의록 · 자동 추출의 범위와 AI의 역할

**결정.** 공고의 평가산식과 적격심사 제출서류는 규칙으로 먼저 추출하고, 실패하거나 부족한 부분만 LLM으로 보완한다. ZIP에 여러 파일이 묶여 있거나 기준서를 자동으로 찾지 못하면 사용자가 해당 파일을 직접 올리는 경로를 둔다.

| 안건 | 논의 결과 |
|---|---|
| 비용과 처리 속도 | 이정근은 현재 규칙으로 산식의 약 86%를 추출하며 LLM 보완 대상은 하루 평균 약 2.2건이라고 공유했다. 조용희가 시험한 서류 추출은 한 건에 약 10원, 로컬 Qwen 4B는 한 건에 약 20분이었다. 서로 다른 작업·환경에서 나온 관측값이다. |
| 제출서류의 정확도 | 독립 최종 테스트 25건 중 필수 서류 목록·제출 조건·원문 근거까지 모두 검증된 공고는 0건이었다. 팀은 우선 공고 한 건을 수집부터 추천까지 연결하고, 이후 규칙과 LLM 보완 결과를 평가하기로 했다. |
| 역할 분담 | 제출서류 추출은 조용희가 만든 기존 코드를 사용한다. 이정근은 공고 수집·DB 쪽을 맡고, 보완 결과를 누가 검증·저장할지는 다음 날 함수 단위로 구체화했다. |
| AI 질의응답 | 공고·업체 DB를 근거로 자연어 질문에 답하고, 실제 심사 결과와 다를 수 있으며 활용 책임은 질문자에게 있음을 고지한다. 강보라가 화면 구성을 맡는다. 조용희는 DB 직접 조회와 벡터 검색(RAG)의 정확도·토큰 사용량을 비교한 뒤 방식을 정하기로 했다. |

## 제출서류 추출 평가 · 사진 2~3

평가 대상 163건을 개발 114건, 검증 24건, 독립 최종 테스트 25건으로 나눴다.

| 평가 범위 | 결과 | 해석 |
|---|---|---|
| 전체 163건의 후보 탐색 | 138건(84.7%)에서 서류 후보 690개 발견 | 공고마다 후보를 하나 이상 찾았는지 집계했다. 나머지 25건도 읽을 수 있는 공고문과 기준서 본문이 있었다. |
| 독립 최종 테스트 25건 | 운영 가능 판정 0건 | 서류가 여러 조항에 흩어져 있거나 대체·면제 조건이 얽혀 있어 완전한 목록과 조건, 근거를 검증하기 어려웠다. 전체 집계의 ‘후보 없는 25건’과는 집계 기준이 다르다. |
| 규칙 수정 후 같은 테스트 자료 재확인 | 미리 선별한 서류명 34/34개, 구체적 제출 조항 75/75줄이 후보에 포함 | 실패 사례를 보고 수정한 뒤의 재평가다. 새로운 공고에서의 정확도는 별도 검증이 필요하다. |
| LLM 보완 | 추가 추출 건수·성공률 미측정 | 다음 평가에서는 원문을 바탕으로 별도 작성한 정답 목록과 대조하고, 조건이 불확실한 항목에는 검토 상태와 근거 문장을 표시한다. |

**산식 추출 흐름(사진 1).** 공유한 설계에서는 원문을 읽기 어려우면 재파싱·OCR 또는 원본 확인으로 돌린다. 읽을 수 있으면 규칙을 먼저 적용한다. 산식 행이 없으면 LLM이 관련 원문 전체에서 추출하고, 검토 대기 행이 있으면 해당 절·표·주석과 기존 행을 대조해 보완한다. 원문 근거와 DB 상태를 검사한 뒤 보완 결과를 `REVIEW`로 저장한다.
