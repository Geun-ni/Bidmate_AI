# SRM OPEN API 첨부파일 누락·입찰참가자격 조사 (2026-11-18, 이정근)

## 조사 방법
- **API**: `https://bigdata.kepco.co.kr/openapi/v1/electContract.do` (companyId=COM01, 최근 30일, 2026-10-19~2026-11-18) → **1,741건** 수신
- **웹 비교**: 적격심사(`bidType=QualifiedEval`)·공사용역 981건 중 무작위 30건 + 기존 테스트 2건(E012607925, E012607914)을 `kepco_srm_poc.py` 방식으로 SRM 웹 전체 첨부목록과 대조
  - **7건만 완료**: 8번째 요청부터 타임아웃 → 연결 끊김 → DNS 실패 → 모든 요청 HTTP 404 (1초 간격 요청인데도 차단된 것으로 보임)
- API 응답의 `filenlinkN`의 `id`와 웹 첨부의 `reference` UUID가 같아서, API가 웹 목록 중 **어떤 파일**을 골랐는지 정확히 매핑함

### 5개 선택 규칙 → **찾지 못함** (7건 기준)
검증해서 **기각한** 가설:
- 파일명 오름차순 / 웹 화면 목록 순서: 아님 (예: E012607914는 웹 13번째가 API 1번)
- 파일 크기 순(작은/큰 순): 아님
- 확장자: hwp·pdf·hwpx 모두 선택됨 (xlsx는 7건 중 한 번도 선택 안 됨 — 표본 적어 규칙으로 보긴 어려움)
- 업로드 UUID 순: 아님

→ 결론: API 5개 안에 필수 파일이 들어갈지는 **미리 알 수 없음**. 7건 중 2건(약 29%)만 API 단독으로 두 파일 확보. (표본 7건이라 비율은 참고치)

## 결론 (4단계안 대입)
1. 원인 파악 → **API 구조상 5개 고정, 선택 규칙 불명** (확인 완료)
2. "API로 대부분 확보" → **해당 안 됨** (7건 중 2건)
3. "누락 조건 파악" → **조건은 못 찾음**. 다만 API 5개 파일명에 공고문/적격심사가 없으면 그 공고만 스크래핑하는 **"누락 감지 후 조건부 스크래핑"**은 구현 가능
4. 웹 스크래핑은 7건 연속 요청만으로 차단됨 → **운영 시 수집량을 최소화해야 함** (공고 등록 시 1회 + 요청 간격 넓게)

## 팀에 결정 요청할 사항
- **파일 확보**: API 우선 + 누락 시에만 1회 스크래핑 (권장) / API로 두 파일이 다 오는 공고만 서비스(약 3할만 남음) / 1회성 스크래핑
- **입찰참가자격**: 지역은 웹 `areaCodeName`으로 가능. 면허는 ① 투찰제한 화면 요청을 추가로 찾아 스크래핑 ② 공고문 hwp를 LLM으로 읽어 추출 중 선택
- 공고문이 `.hwp`(바이너리)와 `.hwpx`가 섞여 있음 → 문서 추출 쪽은 두 형식 모두 처리 필요
