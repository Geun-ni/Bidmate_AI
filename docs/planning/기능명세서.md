# 입찰메이트(Bidmate_AI) 기능명세서

> 문서 버전: **v2.0 (2026-11-18)**  
> 프로젝트: 한국전력공사(SRM) 입찰공고 맞춤 추천·입찰 준비 지원 서비스  
> 상태: **통합 기획 명세 / 구현 및 검증 여부는 항목별 별도 표기**  
> 연관 문서: [업체정보 데이터 정의서 v0.2](./업체정보_데이터_정의서.md)  
> 기존 v1.1의 수집 PoC 이력은 유지하며, 사용자 흐름·화면·평가 기능을 확장한다.

## 1. 서비스 목표 및 범위

입찰메이트는 업체가 등록한 **일반 면허, 제한경쟁입찰자격, 본점 소재지(시·군·구 포함)**를 한국전력공사 SRM 공고의 구조화된 투찰제한 조건과 비교해 **1차 추천 공고 목록**을 제공한다. 사용자는 관심공고를 저장하고, 개별 공고에서 **① 입찰참가자격 및 적격심사 기준 요약, ② 적격심사 점수 간편 계산, ③ 필요서류 체크리스트**를 확인하며 입찰을 준비한다.

**핵심 원칙**
1. 추천 결과는 **SRM 기반 1차 검토**이며 최종 입찰참가 가능 판정이 아니다. 공고문·적격심사기준 및 담당자 확인이 우선한다.
2. **자동심사(Auto)**는 실제 SRM AND/OR 설정과 코드 대응이 검증된 항목만 계산한다. **수동심사(Manual)**는 AND/OR를 추측하지 않고 **추가 확인 필요**로 표시하되, 다른 조건에서 명백한 불일치가 없는 공고는 추천 목록에 노출한다.
3. **주력분야 제한**은 업체 보유 데이터를 수집하지 않으므로 해당 제한이 있는 공고를 **추가 확인 필요**로 표시한다.
4. 문서에서 추출한 정보에는 **원문 출처, 신뢰/검증 상태, 확인 필요 사유**를 제공한다. 이미지·수식 추출 실패를 임의 값으로 보완하지 않는다.
5. **관심공고·체크리스트 완료·예상 점수**는 사용자 관리 정보로서 공식 SRM의 심사 결과가 아니다.
6. 수집/분석/점수 계산은 공고별 기준과 개정일에 종속된다. 표준 적격심사기준은 공고별로 변경될 수 있다.

## 2. 전체 사용자 흐름 및 화면

1. 최초 방문 시 업체정보 입력 화면에서 업체명·본점 전체 주소·SRM 광역 지역 및 시·군·구·보유 면허·제한경쟁입찰자격을 등록한다.
2. 메인 대시보드에서 **왼쪽 약 1/3: 상단 업체정보 카드(정보 입력/수정 버튼), 하단 관심공고 일정 달력**, **오른쪽 약 2/3: 추천 공고 목록**을 보여준다.
3. 추천 공고에는 1차 판정 상태, 근거, 공고명·공고번호·일정, **별 모양 관심공고 토글**을 표시한다. **관심공고만 보기** 필터를 제공한다.
4. 공고를 선택하면 상세 화면으로 이동한다. 상단에는 공고 요약 및 관심공고 버튼, 본문에는 세 탭을 표시한다.
5. **요약 탭:** SRM 제한 조건과 공고문에만 있는 추가 참가자격, 적격심사기준 핵심 내용을 보여준다.
6. **점수 계산 탭:** 당해공사 수행능력 대화형 체크리스트 → 입찰가격 계산 → 가점/감점 체크리스트 → 예상 점수 및 기준점수 비교를 제공한다.
7. **필요서류 탭:** 입찰참가신청·적격심사·조건부 서류를 구분한 체크리스트를 제공한다.
8. 관심공고 일정은 달력에 표시하고, 일정 변경/취소/마감 여부를 함께 안내한다.

## 4. 기능 상세 명세

### 4.1 업체정보 관리

**FUNC-001 업체 기본정보 등록/수정** — **필수, 기획 확정**  
업체명(필수), 사업자등록번호(선택·숫자 10자리), 등기부등본상 본점 전체 주소(필수)를 입력·저장·수정한다. 업체명이나 사업자번호 일치만으로 타 계정 접근 권한을 부여하지 않는다. 업체정보 입력/수정 버튼을 대시보드 좌측 상단에 둔다.

**FUNC-002 일반 면허 등록** — **필수, 기획 확정**  
`면허종류.xlsx`에서 검색·복수 선택한다. 각 면허별 **면허(등록)번호·실제 등록일자**를 필수 입력한다. SRM 코드(예: `A06`)로 저장·비교하며 면허명 유사성으로 자동 동등 처리하지 않는다.

**FUNC-003 본점 소재지 및 SRM 지역 등록** — **필수, 기획 확정**  
전체 주소를 보존하고, SRM 지역그룹(16개 업체 선택 가능) → 해당 **시·군·구 필수 선택**의 종속 선택 UI를 제공한다. `company.area_limit`, `company.sub_area_code`를 저장하고 선행 `0`을 보존한다. 주소와 선택 지역이 불일치하거나 확인 불가면 `address_validation_status=REVIEW/MISMATCH`로 기록하고 자동 충족 처리하지 않는다. **지역그룹 U(전남)·W(광주)는 업체 선택 불가**, 과거 공고 판독용으로만 보존한다.

**FUNC-004 제한경쟁입찰자격 등록** — **필수, 기획 확정**  
SRM 실제 코드 기반으로 복수 선택한다. 자격별 등록번호·등록일자는 받지 않는다. 숫자로 읽히는 `1/2/3/4`도 문자열 저장. **주력분야는 업체 입력 항목에서 제외**한다.

### 4.2 공고·첨부파일 수집

**FUNC-005 공고 기본정보 수집** — **필수, 연동 범위 확인 필요**  
공식 API 기반 공고번호·공고명·발주처·일정·상태를 수집하고 중복 방지, 수집 시각·오류를 기록한다.

**FUNC-006 SRM 상세 및 투찰제한 메타데이터 수집** — **필수, F12 확인/Python 연동 검증 필요**  
공고번호로 SRM 내부 ID를 확인한 뒤 `findBid`의 면허·자격·지역 자동/수동 심사 여부 및 AND/OR 설정을 확보한다. 정상적인 제한 없음(`None` + 빈 상세 응답)과 호출 실패/누락을 구별한다.

**FUNC-007 면허·자격·주력분야·지역 상세 수집** — **필수, F12 확인/Python 연동 검증 필요**  
`findLicenseCodeData`, `findQualifiedCodeData`, `findLicenseMainCodeData`, `findRegionCodeData`를 조회하고 각 응답의 성공 여부·원본·조회 시각을 기록한다. 여러 행은 원본 목록 전체를 보존한다.

**FUNC-008 첨부 목록·원본 다운로드** — **필수, 일부 Python PoC 성공**  
`getAttachments` 등으로 첨부파일을 조회한다. 공고문·적격심사 키워드 파일을 복수 선별·다운로드하되, 이름이 모호한 파일은 누락 가능성을 표시한다. HWP/HWPX/PDF 파일별 다운로드 성공/실패를 기록하고 일부 실패 시 나머지를 계속 처리한다.

### 4.3 1차 투찰제한 판정

**FUNC-009 일반 면허 자동 비교** — **필수, 구현 예정**  
업체 보유 면허코드와 공고 `licenseQualificationCode`를 비교한다. `licenseAutoEvalMethod=Auto`인 경우 `licenseAutoEvalType=And/Or`를 적용한다. `Manual`이면 복수 요구면허가 있어도 AND로 추측하지 않고 `REVIEW`. 설정 누락/해석 불가도 `REVIEW`. 정상적으로 면허 제한이 없음을 확인하면 `NOT_APPLICABLE`.

**FUNC-010 제한경쟁입찰자격 자동 비교** — **필수, 구현 예정**  
`qualifiedQualificationCode`와 업체 자격을 비교하고, **상위 자격이 하위 요구조건을 충족**하는 별도 인정 관계를 먼저 적용한 뒤 `qualifiedAutoEvalType=And/Or`로 결합한다.

| 하위 → 상위 | 업체 보유 상위 자격이 충족하는 하위 요구조건 |
|---|---|
| `1 < B < C` | `B→1`, `C→1,B` |
| `D < E` | `E→D` |
| `M < O` | `O→M` |
| `U < V` | `V→U` (변압기2급이 1급보다 상위) |
| `W < X < Y` | `X→W`, `Y→W,X` |

모든 자격은 자기 코드와 일치한다. 다른 자격은 검증된 인정 관계가 없으면 정확한 코드 일치만 허용한다. 이 관계는 사용자 확인 공고문을 기반으로 하며 **서비스 운영 전 최신 공식 적용 범위 확인 필요**. 자격 `U/W`는 지역 `U/W`와 별개다. `qualifiedAutoEvalMethod=Manual` 또는 결합 규칙 불명확 시 `REVIEW`.

**FUNC-011 지역제한 자동 비교** — **필수, 구현 예정**  
`regionLimitAutoEvalMethod=Auto`인 공고에서 `areaCode`와 `company.area_limit`를 비교하고, `subAreaCode`가 있으면 `company.sub_area_code`까지 비교한다. `subAreaCode=null`은 해당 광역 그룹 전체 제한. 실제 사례: `E012300731` 강원 `F` 전체, `E012300540` 강원 `F`/영월군 `011008`. 공고에 여러 지역 행이 있으면 결합 의미를 확인한다. 지역 제한 없음은 정상 조회 확인 시에만 `NOT_APPLICABLE`. 과거 공고의 지역코드 `U/W`는 `I`로 자동 치환하지 않고 `REVIEW` 및 **공고 담당자에게 문의** 안내.

**FUNC-012 주력분야·수동심사 확인** — **필수, 구현 예정**  
`findLicenseMainCodeData`에 하나 이상 제한이 존재하면 업체 보유 주력분야 데이터가 없으므로 `license_main_status=REVIEW`. 정상 조회된 빈 배열만 `NOT_APPLICABLE`. `licenseMainAutoEvalType`이 존재해도 업체 보유 정보가 없어 자동 충족 판정하지 않는다. 수동심사 면허/자격/지역 조건도 AND/OR를 임의 추론하지 않고 `REVIEW`.

**FUNC-013 종합 판정 및 추천 노출** — **필수, 구현 예정**  
항목 상태는 `MATCH/MISMATCH/REVIEW/NOT_APPLICABLE`. **명확한 불일치가 하나라도 있으면 `MISMATCH` 우선**, 불일치가 없고 하나라도 불확실하면 `REVIEW`, 나머지는 `MATCH`. 추천 목록에는 **MATCH + REVIEW**를 표시하되 REVIEW는 **“입찰참가자격 확인 필요”** 배지와 사유를 반드시 표시한다. **MISMATCH는 기본 추천 목록에서 제외**한다. SRM 자동심사 충족은 최종 입찰자격을 보장하지 않는다. 문서상 추가 자격(실적, 대기업 제한, PQ, 공동수급, 기술자, 제재 등)은 별도 분석한다.

### 4.4 메인 대시보드 및 관심공고

**FUNC-014 메인 대시보드** — **필수, 화면 기획 확정**  
데스크톱 기준 **왼쪽 약 1/3**: 상단 업체정보 요약(업체명·주소·면허/자격 및 **정보 입력/수정**), 하단 관심공고 달력. **오른쪽 약 2/3**: 추천 공고 목록. 작은 화면에서는 세로 배치한다. 업체 미등록 시 입력 유도 상태를 표시한다.

**FUNC-015 추천 공고 목록/필터/상세 이동** — **필수, 화면 기획 확정**  
공고명·공고번호·발주처·입찰참가신청/투찰 일정·지역·면허·자격 판정·추가 확인 사유·마감 여부를 표시한다. **관심공고만 보기** 필터, 기본 정렬(마감 임박 순 등), 공고 클릭 시 상세 이동. 마감·취소·정정 공고는 현재 투찰 가능 공고로 오인하지 않도록 구분한다.

**FUNC-016 관심공고 별표 및 일정 달력** — **필수, 화면 기획 확정**  
공고 카드와 상세 상단에 별 모양 토글을 제공한다. 업체/사용자 단위 관심 상태를 저장하고 필터와 달력에 즉시 반영한다. 관심공고의 **입찰참가신청 시작·마감, 투찰 시작·마감, 개찰, 적격심사 서류 제출기한(확인된 경우)**을 이벤트로 표시한다. 일정 출처와 확정/미확정 상태를 구분하며 정정 공고 발생 시 최신 일정으로 갱신한다. 날짜 클릭 시 공고 상세로 이동한다.

### 4.5 공고 상세 — 3-1 입찰참가자격 및 적격심사 기준 요약 탭

**FUNC-017 참가자격 요약 및 추가조건 분석** — **필수, 문서 분석 검증 필요**  
공고문 HWP/HWPX/PDF의 텍스트·표를 분석하여 **SRM 구조화 조건 / 공고문 추가 조건**을 구분해 표시한다. 각 조건의 근거 문서·항목·확인 상태(자동 확인/업체 직접 확인/원문 확인 필요)를 제공한다. 자동 확인되지 않은 조건은 “확인됨”으로 표시하지 않는다.

**당림리 공고문 기반 화면 검증 예시(실제 사용자 업체 판정값 아님)**
- 전기공사업 등록 및 강원특별자치도 본점 소재지.
- **배전활선·무정전 동종실적**, 공고일 전일 기준 최근 **10년 이내** 협회 공시 **1건**, **VAT 제외 금액이 추정가격 421,687,077원의 1/3 이상**(정확한 원 단위 판단은 공고 규정 확인). 개찰 후 실적 확인; SRM 면허/지역만으로 확인 불가.
- 공동도급 **해당 없음**, 일정·G2B/SRM 등록, 대기업 전기공사업자 참여 제한, 제재 관련 제한 등.
- 공고문상 **담당자 재확인 심사**에 따라 투찰 후 부적격·무효 가능성 안내.
- 예시 공고의 입찰참가신청 마감 **2026-11-11 18:00**, 투찰 마감 **2026-11-12 14:00**은 이미 경과한 일정으로 표시.

**FUNC-018 적격심사 기준 요약** — **필수, 문서 분석 검증 필요**  
기준서에서 배점, 세부 평가요소, 제출 증빙, 산식·반올림·상한·결격 규정, 낙찰자 결정 기준 점수를 추출하여 요약한다. 추출 실패한 표/이미지 수식은 **“원문 확인 필요”**로 표시한다. 관련 원본 파일 다운로드/열람을 제공한다.

**배전공사 총액계약 적격심사기준(추정가격 3억~10억 미만) 검증 예시:** 수행능력 **30점(시공경험 18 + 경영상태 12)**, 입찰가격 **70점**, **낙찰자 결정 기준 95점**(공고별 기준 확인), 가점/감점 및 기술자 보유 미달 **-10점**. 시공경험 18점은 **최근 5년 실적 14점 + 사업소 지리·지형·배전계통 숙지도 4점**. 예시 기준서에 기재된 사정액 **463,855,784원(VAT 포함)**. 단, 이 기준서는 **표준안이며 공고별로 달라질 수 있음**.

### 4.6 공고 상세 — 3-2 적격심사 점수 간편 계산 탭

**FUNC-019 당해공사 수행능력 대화형 체크리스트** — **필수 목표, 문서 추출·규칙 검증 필요**  
입찰가격 외 평가항목을 **기준서에서 확인된 배점·보기·산식·기준금액**에 맞춰 입력형/단일 선택형/확인형으로 생성한다. 업체 고유 정보(실적·재무·신용등급·사업소 소재지 등)는 직접 입력받는다. **입력되지 않은 항목을 0점으로 확정하지 않고 미산정**으로 표시한다.

- **시공경험 14점 숫자 입력형:** 기준서에서 확인한 `해당공사 공사원가 예정가격산출 기초조서상의 사정액`은 시스템 제공(예시 463,855,784원), **최근 5년 해당 업종 실적 누계액**은 업체 입력. 예시 산식은 `(실적 누계액 / 사정액) × 14`이며 상한 **14점**, 실제 기준서의 실적 인정범위·VAT·공동도급 비율·**소수점 셋째 자리 반올림** 규정을 확인한 경우에만 계산한다. 이미지 속 분수/산식이 추출되지 않으면 원문 검증 후 활성화한다.
- **지리·지형/배전계통 숙지도 4점 단일 선택형:** 해당사업소 **4점**, 인접사업소 **3점**, 동일 광역지역의 비인접사업소 **2점**, 광역지역 밖 **0점**. 기준서에서 **해당/인접 사업소 관할 목록을 추출**해 표시한다. 이번 예시의 인접사업소는 **홍천·인제·화천·양구지사**. 사업소 관할과 SRM 시군구 코드의 자동 매핑은 검증 전이므로 **사용자 직접 선택**을 기본으로 한다. 공동도급 시 별도 지분 계산 규칙을 확인한다.
- **경영상태 12점:** 사용자에게 **재무비율 평가**(부채비율 5.5, 유동비율 5.5, 영업기간 1) 또는 **신용평가등급 평가**(최대 12) 중 하나를 선택하게 한다. 기준서의 등급표·업종 평균치·예외 규정이 정확히 확인된 경우만 점수를 산출한다. 예시 기준서의 2025년 평균 **부채비율 120.77%, 유동비율 142.57%**는 해당 문서에만 적용한다. 신용등급표 인식 실패 시 직접 점수 확인형으로 전환한다.
- 평가항목별 **원문 출처/확인 필요 표시**, 점수·상한·반올림 적용 근거, 사용자 입력 수정·재계산을 제공한다.

**FUNC-020 입찰가격 점수 — 1안: 산식 인식·자동 계산** — **조건부/기술검증 후 채택**  
적격심사기준 HWP/HWPX/PDF에서 **`주1) 입찰가격 평가산식` 등 산식 위치를 식별**하고, 텍스트·수식 객체·이미지/표 영역의 수식을 추출·정규화한다. **수식 자체, 변수 정의, 예외 조건, 상·하한, 반올림 자리수**가 모두 검증된 경우에만 해당 공고의 계산식을 활성화한다.

- 입력: **입찰가격, 예정가격, A 금액** 등 해당 산식이 요구하는 값. 공고에서 확인 가능한 값만 자동 채움; 미확정 예정가격·A는 임의 추정하지 않음.
- 출력: 계산된 **가격점수(70점 만점 등 공고별 배점)**, 적용 산식, 변수, 중간 계산값, 예외·반올림 처리, 기준서 근거.
- 이번 기준서의 텍스트 추출 결과는 **`주1) 입찰가격 평가산식`, `평점(점) =` 이후 핵심 수식 본문이 비어 있음**. 따라서 **산식 자동 인식 성공으로 간주하지 않음**. 다만 `A` 구성항목, **비율 소수점 다섯째 자리 반올림**, 특정 비율 범위의 **65점 적용**, **최저 2점** 등의 주변 규정은 추출됨. **원본 이미지/수식 객체 판독과 사람의 검증이 선행**되어야 한다.
- 산식/예외 중 하나라도 불명확하면 자동 점수를 **보류**하고 **2안으로 전환**한다. **낙찰하한율만으로 산식을 역산하지 않는다.**
- 배포 전 실제 공고 여러 유형의 산식·경계값 테스트, 담당자 검증, 수식 버전 관리 필요.

**FUNC-021 입찰가격 점수 — 2안: 직접 계산기 제공** — **MVP 우선 대안**  
자동 인식이 어려운 공고에도 사용할 수 있는 **사칙연산(+ − × ÷), 괄호, 절댓값, 소수 계산기**를 제공한다. 낙찰하한율(SRM 값이 있으면), 가격 배점, 적격심사기준 원본 다운로드/열람을 함께 표시한다. 사용자는 **원문의 산식을 직접 보고 숫자와 연산을 입력**한다. 계산 결과는 **수학적 계산 결과**이며, 공식 입찰가격점수나 적격심사 통과 여부로 자동 확정하지 않는다. **입력식·결과 복사/초기화**를 지원한다. 사용자 입력 결과를 총점 시뮬레이션에 반영하려면 **“원문과 계산 결과를 직접 확인했습니다”** 확인을 거치고 **사용자 입력 추정치**로 표시한다.

**1안·2안 선택 정책:** MVP는 **2안을 기본 제공**, 1안은 공고별 산식이 정확히 추출·검증된 경우에만 선택적으로 활성화하는 단계적 접근을 권장한다. 두 안은 문서에 모두 유지하며 최종 채택은 기술검증 후 결정한다.

**FUNC-022 가점/감점 대화형 체크리스트** — **필수 목표, 세부기준 검증 필요**  
가격 계산기 **아래**에 배치한다. 일반신인도(예: 일자리 창출, 건설재해·제재, 불공정 하도급), 건설안전신인도, 부정당 시공경험(직원 금품제공 **-0.8**, 일시정전 유발 **-0.4**), 기술자 보유 미달 **-10** 등 기준서에 실제 명시된 항목을 **해당/비해당/확인 필요** 체크리스트로 구성한다. 등급·횟수·적용기간·증빙 조건이 있는 항목은 단순 체크만으로 점수를 확정하지 않고 추가 선택/입력과 검증을 요구한다. **가점이 95점 미달을 언제나 보완할 수 있다고 표현하지 않는다.** 기준서에 따라 가감점 상계, 항목별 범위 및 **시공경험+경영상태+가점/감점 합계의 수행능력 30점 상한**을 적용한다. 기술자 보유 미달과 같은 결격/감점 항목은 별도 처리한다. 이미지 시안의 임의 예시 점수를 실제 산정 규칙으로 사용하지 않는다.

**FUNC-023 예상 점수·낙찰자 결정 기준 비교** — **필수 목표, 계산 검증 필요**  
상단에 **공고별 낙찰자 결정 기준 점수(예시 95점)**를 고정 표시한다. 수행능력·입찰가격·가감점·결격의 **계산 가능 점수/미산정 점수**를 구분하고, 모든 필수 항목이 검증된 경우에만 **예상 총점 및 기준 대비 부족/초과 점수**를 표시한다. 일부 미확정 시 **“산정 보류/입력 중”**을 표시하고 95점 통과·미달을 단정하지 않는다. 예상 점수는 업체 제공 정보와 추출된 기준에 근거한 **참고용 시뮬레이션**으로 안내한다.

### 4.7 공고 상세 — 3-3 필요서류 탭

**FUNC-024 필요서류 자동 추출·분류** — **필수 목표, 문서 분석 검증 필요**  
공고문과 적격심사기준의 서류 요구사항을 분석하여 **① 입찰참가신청 단계 ② 적격심사 대상자 증빙 단계 ③ 조건부 제출/최종 확인**으로 분류한다. 항목마다 **서류명, 제출 목적, 필수/조건부/해당 없음, 제출 시점·방법, 원문 근거, 확인 필요 여부**를 표시한다. **공고문에 없는 서류를 필수로 단정하지 않는다.**

**당림리 공고문 기반 검증 예시**
- 입찰참가신청서(전자 작성), **입찰보증금 지급각서**(일반적으로 입찰금액의 5% 이상; 특정 제재 이력 등 예외는 현금/보증서 납부), G2B 경쟁입찰 참가자격 등록 및 SRM 회원등록 확인.
- **공동수급협정서: 공동도급 해당 없음 → 비대상**, 공고문상 별도 스캔 첨부서류 **“해당사항 없음”**.
- 적격심사 단계: **최근 10년 이내 동종실적 1건 실적증명서**(개찰 후 해당 조건 검증용), **최근 5년 해당업종 실적 확인 자료**, 경영상태 **재무비율 확인서류 또는 신용평가등급 자료**, 본점 소재지 증빙, 해당 시 기술자·가점 증빙.
- **입찰참가신청 마감 2026-11-11 18:00** 등 마감은 원문 확인 후 표시. 공고문에 명시된 단계와 서류 제출 마감이 다른 경우 혼동하지 않도록 한다.
- 적격심사 대상자에게 실제 요구되는 서류·인정 범위는 공고문과 심사 담당자 안내로 최종 확인한다.

**FUNC-025 체크리스트 진행률·저장** — **필수, 구현 예정**  
서류별 준비/미준비/해당 없음/확인 필요 상태를 사용자가 변경·저장한다. 필수 서류 기준 진행률을 표시하고 공고별로 보존한다. 공고문 정정 시 원문과 비교해 변경된 요구사항을 표시하고 기존 체크 상태 재확인을 요청한다. **체크 완료는 제출 완료나 기관 승인 의미가 아니다.**

## 6. 판정/화면 표시 상태

| 상태 | 사용자 표시 | 목록 처리 |
|---|---|---|
| `MATCH` | SRM 1차 조건 충족 | 추천 목록 표시; 공고문 별도 확인 안내 |
| `REVIEW` | **입찰참가자격 확인 필요** | 추천 목록 표시, 사유 강조 |
| `MISMATCH` | SRM 조건 불일치 | 기본 추천 목록 제외 |
| `NOT_APPLICABLE` | 해당 제한 없음 | 항목별 표시, 종합 판정에서 불이익 없음 |
| 문서 분석 실패 | 원문 확인 필요 | 분석 결과 추측 금지 |
| 점수 미산정 | 입력 중 / 산식 확인 필요 | 총점 통과 여부 단정 금지 |
| 공고 마감/취소 | 마감 / 취소 / 정정 | 현재 신청 가능한 공고와 구분 |

**중요:** `REVIEW` 공고를 숨기지 않는 것이 서비스 정책이다. 다만 `MISMATCH`가 명백하면 다른 조건이 수동/미확인이라도 기본 추천 대상에서 제외한다. 사용자의 체크리스트 선택이 SRM 공식 판정 상태를 변경하지 않는다.

## 8. 오류·보안·운영 원칙

- SRM 호출 실패·빈 배열·제한 없음은 서로 다른 상태로 저장한다. 조회 실패를 `NOT_APPLICABLE`로 처리하지 않는다.
- HWP/HWPX/PDF의 텍스트·표·이미지·수식은 추출 성공 여부를 개별 관리한다. 불확실한 금액·배점·산식·관할 사업소는 추정하지 않는다.
- 사용자가 입력한 실적·재무·증빙 정보는 **미검증**이며, 자동 추천과 점수 산출의 출처를 구분한다.
- 수식 자동 계산은 0으로 나누기, A 금액, 소수점 반올림, 경계 구간, 상한/하한, 공동도급 규칙을 테스트한다.
- 적격심사 문서의 표준안과 개별 공고 첨부의 차이를 구분한다. 개별 공고 및 정정 공고가 우선한다.
- 관심공고·체크리스트·점수 초안은 사용자/업체별 접근 권한을 확인하고 변경 이력을 관리한다.
- 개인·업체 정보, 다운로드 문서의 보관기간·접근권한 및 이용조건은 배포 전 별도 확정한다.
