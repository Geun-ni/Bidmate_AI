# 입찰메이트(Bidmate_AI) 기능명세서

> 문서 버전: v1.1 (2026-11-17 개정안)  
> 프로젝트: 팀 프로젝트 / 한전 입찰공고 맞춤 추천 서비스  
> 문서 상태: 기획 개정안 (구현 및 검증 상태는 별도 표기)

## 1. 서비스 개요

입찰메이트는 한국전력공사 입찰공고를 수집하고, 업체가 등록한 **보유 면허**와 **등기부등본상 본점 소재지**를 공고의 참가자격과 비교해 적합한 공고를 추천하는 서비스다. 공식 Open API로 공고 기본정보를 수집하고, 한전 SRM 웹의 내부 요청으로 공식 API에 없는 첨부파일·면허·지역제한 정보를 보완한다.

### 핵심 이용 흐름

1. 업체 담당자가 보유 면허를 목록에서 검색하여 복수 선택한다.
2. 등기부등본에 기재된 본점 **전체 주소**를 입력한다.
3. 시스템이 한전 입찰공고를 수집하고 SRM에서 공고별 상세정보를 조회한다.
4. 공고의 요구 면허 및 지역제한 정보를 수집한다.
5. 업체 정보와 공고 조건을 비교하여 **1차 조건 충족 / 조건 불일치 / 추가 확인 필요**로 분류한다.
6. 추천 목록에 결과와 판단 근거를 표시한다.
7. 필요시 공고문 및 적격심사기준 첨부파일을 수집·분석한다.

> SRM의 `/router`는 공식 외부 연동용으로 보장된 API가 아닌 웹 내부 요청이다. 팀 프로젝트 PoC에서 활용하며, 요청 구조 변경·세션 만료·조회 실패 가능성을 고려한다.

## 2. 데이터 출처

| 데이터 | 출처 / 수집 방식 | 비고 |
|---|---|---|
| 입찰공고 기본정보 | 한전 공식 Open API | 공고번호 등 기본정보 |
| SRM 공고 ID 및 상세정보 | SRM `getPageList`, `findBidBasicInfo` | Python PoC 성공 |
| 첨부파일 목록 | SRM `getAttachments` | 테스트 공고에서 14개 조회 성공 |
| 첨부파일 원본 | SRM `downloadAttachment.do` | HWP 다운로드 성공 |
| 공고 요구 면허 | SRM `findLicenseCodeData` | 브라우저 응답 확인, Python 연동 미검증 |
| 공고 지역제한 | SRM `findRegionCodeData` | 브라우저 응답 확인, Python 연동 미검증 |
| 면허 검색 목록 | 제공된 `면허종류.xlsx` | 면허명·면허코드 사용 |
| 업체 보유 면허 | 사용자 검색·복수 선택 | 코드 저장 |
| 업체 본점 주소 | 사용자 직접 입력 | 등기부등본 기준 전체 주소 |

## 3. 기능명세

### 3.1 업체 정보 등록

#### FUNC-001. 업체 기본정보 등록 및 수정
- **목적:** 업체별 공고 추천을 위한 기본정보를 저장한다.
- **입력:** 보유 면허 목록, 본점 전체 주소.
- **처리:** 필수값 검사 후 업체 정보 저장; 이후 수정 가능.
- **출력:** 등록된 업체 정보.
- **예외:** 필수값 누락 시 저장 제한.
- **우선순위:** 필수 / **상태:** 기획 확정.

#### FUNC-002. 면허 검색 및 복수 선택
- **목적:** `면허종류.xlsx` 기반으로 면허를 검색·선택한다.
- **입력:** 면허명 또는 면허코드 검색어.
- **처리:** 검색 결과 표시, 복수 선택, 중복 선택 방지.
- **출력:** 면허코드 목록과 표시용 면허명.
- **규칙:** 비교와 저장에는 **면허코드**를 사용한다. 면허명이 비슷하다는 이유로 다른 코드를 동등하게 취급하지 않는다.
- **예:** `A06` = 전기공사업.
- **우선순위:** 필수 / **상태:** 기획 확정.

#### FUNC-003. 본점 소재지 입력 및 행정구역 추출
- **목적:** 본점 주소를 공고의 지역제한과 비교할 수 있도록 구조화한다.
- **입력:** 등기부등본에 기재된 본점 전체 주소.
- **처리:** 원본 주소 보존, 시·도 및 시·군·구 추출·정규화, SRM 지역코드와 매핑.
- **출력:** 원본 주소, 정규화된 행정구역.
- **예외:** 주소를 해석할 수 없으면 추가 확인 필요.
- **유의:** 직접 입력한 주소가 실제 등기부등본과 일치하는지 검증하는 기능은 별개다.
- **우선순위:** 필수 / **상태:** 기획 확정.

### 3.2 공고 수집

#### FUNC-004. 한전 입찰공고 기본정보 수집
- **입력:** 조회 기간 및 공고번호 등의 검색 조건.
- **처리:** 공식 Open API 조회, 공고번호 기준 중복 방지, 수집 시각 및 상태 기록.
- **출력:** 공고 목록과 기본정보.
- **예외:** API 오류·결과 없음 구분.
- **우선순위:** 필수 / **상태:** 연동 범위 논의.

#### FUNC-005. SRM 공고 검색 및 상세정보 조회
- **입력:** 공고번호.
- **처리:** `getPageList`로 내부 공고 ID 조회 → `findBidBasicInfo`로 상세정보 및 `attachFileGroupId` 확보.
- **출력:** 내부 공고 ID, 첨부파일 그룹 ID 및 상세정보.
- **예외:** 공고 미검색, 중복 검색 결과, 세션 오류.
- **우선순위:** 필수 / **상태:** **Python PoC 성공**.

### 3.3 첨부파일 수집

#### FUNC-006. 전체 첨부파일 목록 조회
- **입력:** `attachFileGroupId`.
- **처리:** SRM `getAttachments` 요청.
- **출력:** 파일명(`name`), 다운로드 ID(`id`), 확장자, 크기 등.
- **우선순위:** 필수 / **상태:** **Python PoC 성공**. 공고 `E012607925`에서 14개 조회.

#### FUNC-007. 공고문·적격심사 파일 자동 선별
- **입력:** 첨부파일 목록.
- **처리:** 파일명에서 공백을 제거한 뒤 **`공고문` 또는 `적격심사`** 포함 여부 확인.
- **출력:** 키워드에 일치하는 모든 파일 목록.
- **규칙:** 번호·추가 문구와 무관하게 부분 일치; 복수 파일 허용.
- **예외:** `붙임2.hwp`처럼 파일명에 키워드가 없으면 선별되지 않을 수 있음.
- **우선순위:** 필수 / **상태:** 코드 반영, 추가 실행 검증 필요.

#### FUNC-008. 선별 첨부파일 다운로드
- **입력:** 다운로드 대상 파일 ID.
- **처리:** `downloadAttachment.do` 요청 → 파일 응답·크기·지원 형식 검사 → 공고번호별 폴더 저장.
- **출력:** 저장된 파일 및 파일별 성공·실패 로그.
- **저장 경로 예:** `downloads/E012607925/2. 적격심사기준.hwp`.
- **예외:** 한 파일이 실패해도 다른 파일 다운로드는 계속 시도.
- **우선순위:** 필수 / **상태:** **단일 HWP 다운로드 PoC 성공**, 키워드 기반 복수 다운로드는 추가 검증 필요.

### 3.4 공고 참가자격 수집

#### FUNC-009. 공고 요구 면허 조회
- **입력:** SRM 공고 식별정보.
- **처리:** `smartsuit.ui.etnajs.pro.rfx.BidDetailController.findLicenseCodeData` 호출.
- **출력:** 요구 면허코드(`licenseQualificationCode`), 면허명(`licenseQualificationCodeName`).
- **규칙:** 복수 면허의 AND/OR 관계가 확인되지 않으면 임의로 판정하지 않는다.
- **예외:** 조건 미지정과 조회 실패를 구분.
- **우선순위:** 필수 / **상태:** 브라우저 응답 확인, Python 연동 검증 필요.

#### FUNC-010. 공고 지역제한 조회
- **입력:** SRM 공고 식별정보.
- **처리:** `smartsuit.ui.etnajs.pro.rfx.BidDetailController.findRegionCodeData` 호출.
- **출력:** `areaCode`, `areaCodeName`, `subAreaCode`, `subAreaCodeName`.
- **예:** `I` / `전남광주` (세부 지역코드 null).
- **규칙:** 실제 포함 행정구역은 별도 지역코드 매핑으로 확인하며, 매핑 불명확 시 추가 확인 필요.
- **우선순위:** 필수 / **상태:** 브라우저 응답 확인, Python 연동 검증 필요.

### 3.5 업체별 자격 비교 및 추천

#### FUNC-011. 면허 조건 자동 비교
- **입력:** 업체 보유 면허코드 목록, 공고 요구 면허코드 목록.
- **처리:** 코드 기준 비교; 확인된 AND/OR 조건 적용.
- **출력:** 충족 / 불일치 / 추가 확인 필요 및 근거.
- **예외:** 복수 면허 관계 불명확 시 추가 확인 필요.
- **우선순위:** 필수 / **상태:** 구현 예정.

#### FUNC-012. 지역제한 자동 비교
- **입력:** 업체 본점 주소에서 추출한 행정구역, 공고 지역코드.
- **처리:** 지역코드 매핑 후 광역·세부 지역 조건 비교.
- **출력:** 충족 / 불일치 / 추가 확인 필요 및 근거.
- **예외:** 지역코드 미확인, 주소 해석 실패, 조회 실패 시 추가 확인 필요.
- **우선순위:** 필수 / **상태:** 구현 예정.

#### FUNC-013. 참가자격 1차 종합 판정
- **입력:** 면허 및 지역 비교 결과.
- **출력:** **1차 조건 충족 / 조건 불일치 / 추가 확인 필요**.
- **판정 규칙:**
  - 면허·지역 모두 충족 → 1차 조건 충족.
  - 어느 하나라도 명확히 불일치 → 조건 불일치.
  - 불일치가 없지만 하나라도 불확실 → 추가 확인 필요.
- **유의:** 실적, 시공능력, 공동수급 등 다른 조건은 별도 검토가 필요하므로 최종 참가 가능 여부로 표시하지 않는다.
- **우선순위:** 필수 / **상태:** 구현 예정.

#### FUNC-014. 업체 맞춤 공고 필터링
- **입력:** 수집 공고, 업체 정보, 1차 판정 결과.
- **처리:** 1차 조건 충족 공고 우선 노출, 추가 확인 공고 별도 표시, 불일치 공고 구분.
- **출력:** 업체별 공고 목록.
- **우선순위:** 필수 / **상태:** 구현 예정.

#### FUNC-015. 자격 비교 근거 상세보기
- **입력:** 업체·공고별 면허 및 지역 비교 결과.
- **출력:** 요구 면허/보유 면허, 제한 지역/본점 지역, 항목별 판정, 종합 결과, 추가 확인 사유.
- **우선순위:** 필수 / **상태:** 구현 예정.

### 3.6 문서 분석 및 확장

#### FUNC-016. 공고문 내용 추출
- **입력:** 다운로드한 HWP/HWPX/PDF 공고문.
- **처리:** 텍스트·표에서 참가자격, 실적, 시공능력, 공동수급 등 조건 추출.
- **출력:** 구조화된 조건 및 확인 필요 항목.
- **우선순위:** 확장 / **상태:** 기술검증 필요.

#### FUNC-017. 적격심사기준 분석
- **입력:** 적격심사 관련 첨부파일.
- **처리:** 평가항목·배점·산정기준 추출 및 구조화.
- **출력:** 평가기준 데이터.
- **우선순위:** 확장 / **상태:** 기술검증 필요.

#### FUNC-018. 적격심사 예상 점수
- **입력:** 공고별 심사 산식, 업체별 추가 평가정보.

## 8. 권장 개발 순서

1. **업체 등록:** 엑셀 기반 면허 검색·복수 선택, 본점 전체 주소 저장.
2. **SRM 자격 수집:** `findLicenseCodeData`, `findRegionCodeData` Python 연동 검증.
3. **1차 자동 필터:** 면허코드 비교, 주소·지역코드 매핑, 판정 및 근거 표시.
4. **첨부파일 수집:** 키워드 기반 복수 파일 다운로드 검증 및 안정화.
5. **문서 분석 확장:** 공고문·적격심사기준 분석, 필요한 업체 평가정보 확보 후 예상 점수 산출.

## 9. 핵심 범위 정의

입찰메이트의 우선 구현 범위는 **업체 보유 면허와 본점 소재지를 SRM의 공고 참가자격과 비교해 적합한 공고를 선별하는 기능**이다. HWP 등 문서 분석은 1차 필터링을 보완하는 확장 기능으로 단계적으로 구현한다.
