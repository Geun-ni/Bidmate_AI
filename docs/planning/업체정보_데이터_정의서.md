# 입찰메이트(Bidmate_AI) 업체정보 데이터 정의서

> **문서 버전:** v0.2  
> **작성일:** 2026-11-17  
> **상태:** 기획 개정안 (SRM 응답 기반 1차 심사 규칙 반영)  
> **대상:** 한전 SRM 입찰공고 추천 및 1차 참가자격 판정

## 1. 개요 및 설계 원칙

업체 기본정보, 일반 면허, 제한경쟁입찰자격, 본점 소재지 및 SRM 지역그룹을 저장하여 공고의 참가자격과 비교한다.

- 업체 입력정보는 별도 검증 전까지 **사용자 제공 정보**로 간주한다.
- SRM에서 확인한 코드를 우선 사용한다. 내부 코드와 SRM 공식 코드는 구별한다.
- 면허 및 제한경쟁입찰자격은 복수 등록한다.
- 판정은 법적 참가 가능 여부가 아닌 **1차 검토**이다.
- 조회 실패·코드 해석 불명확은 '제한 없음'이 아니라 `REVIEW`이다.

## 3. 업체 기본정보 — `company`

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `company_id` | UUID | Y | PK, 시스템 생성 |
| `company_name` | VARCHAR(200) | Y | 사용자 입력 업체명 |
| `business_registration_no` | VARCHAR(10) | N | 숫자 10자리, 미입력 시 NULL |
| `head_office_address` | VARCHAR(500) | Y | 등기부등본상 본점 전체 주소 |
| `area_limit` | VARCHAR(10) | Y | SRM 지역그룹 코드, FK |
| `sub_area_code` | VARCHAR(30) | Y | SRM 시·군·구 `code` 값, `srm_region_district_master`와 대응; 문자열로 앞자리 0 보존 |
| `address_validation_status` | VARCHAR(20) | Y | `MATCH`, `MISMATCH`, `REVIEW` |
| `created_at` | DATETIME | Y | 생성일시 |
| `updated_at` | DATETIME | Y | 수정일시 |

**규칙:** 업체명은 고유키가 아니며, 동일한 업체명도 별개의 `company_id`를 가질 수 있다. 사업자등록번호는 선택이며 하이픈 제거 후 문자열 10자리로 저장한다. 형식만 확인하고 진위는 검증하지 않는다. 번호가 일치해도 업체정보를 자동 통합하거나 다른 사용자의 접근 권한을 부여하지 않는다. 본점 주소와 사용자가 선택한 SRM 지역그룹 **및 시·군·구**의 일치 여부를 점검하며 불명확한 경우 `REVIEW`로 처리한다. 주소 원문은 유지하고, 광역 지역과 시·군·구는 SRM 지역제한 목록의 종속 선택지로 입력받는다. 행정구역과 SRM 코드의 대응을 확인하지 못하면 자동 충족 처리하지 않는다.

### 5.3 `restricted_qualification_equivalence` — 상하위 인정 규칙

| 필드 | 타입 | 설명 |
|---|---|---|
| `held_qualification_code` | VARCHAR(20) | 업체 보유 자격코드, 복합 PK/FK |
| `accepted_requirement_code` | VARCHAR(20) | 충족 가능한 공고 요구 자격코드, 복합 PK/FK |
| `is_active` | BOOLEAN | 규칙 적용 여부 |
| `source_note` | TEXT | 근거 공고문·확인 이력 및 적용 조건 |

**판정 방향:** 업체가 상위 자격을 보유하면 하위 자격 요구조건을 충족한다. 역방향은 인정하지 않는다. 다음은 사용자가 공고문에서 확인한 규칙으로, 서비스 운영 전 적용 범위·최신 기준을 검증한다.

| 관계(하위 → 상위) | 업체 보유 코드 → 충족 가능한 요구 코드 |
|---|---|
| `1 < B < C` | `1→1`; `B→1,B`; `C→1,B,C` |
| `D < E` | `D→D`; `E→D,E` |
| `M < O` | `M→M`; `O→M,O` |
| `U < V` | `U→U`; `V→U,V` (변압기 2급이 1급보다 상위) |
| `W < X < Y` | `W→W`; `X→W,X`; `Y→W,X,Y` |

그 밖의 자격은 검증된 별도 인정 관계가 없으면 **동일 코드만 충족**한다. `U`, `W`는 여기서는 **제한경쟁입찰자격 코드**이며 지역그룹의 동명 코드와 별개의 코드 체계다. 공고 요구 자격별로 인정 관계를 먼저 평가한 뒤 `qualifiedAutoEvalType=And/Or`를 적용한다. `Manual` 또는 AND/OR 불명확 시 `REVIEW` 처리한다.

## 6. SRM 지역그룹 및 세부 지역

### 6.1 코드 출처

SRM `findAreaRestrictList` 응답:

```json
{
  "codeId": "F_011013",
  "code": "011013",
  "name": "춘천시",
  "areaLimit": "F",
  "subAreaCode": "011013",
  "areaLimitName": "강원",
  "subAreaYn": true
}
```

`areaLimit`를 지역그룹 식별자로 사용한다. `code`, `codeId`는 앞자리 0을 보존하는 문자열로 저장한다. 지역그룹은 사용자가 직접 선택하며 주소는 원문 보존한다.

| 코드 | 이름 | 업체 선택 |

| C | 충북 | 가능 |
| D | 대전 | 가능 |

| 필드 | 타입 | 설명 |
|---|---|---|
| `code_id` | VARCHAR(50) | PK, SRM `codeId` |
| `area_limit` | VARCHAR(10) | 상위 그룹 FK |
| `region_code` | VARCHAR(30) | SRM `code` |
| `region_name` | VARCHAR(100) | SRM `name` |

| `si_name` | VARCHAR(50) | `region_name`의 시 (없으면 NULL) |

예시: `F_011013 / F / 011013 / 춘천시`, `G_021001 / G / 021001 / 가평군`.
시/군/구 나누기: `춘천시` → 시=춘천시, `가평군` → 군=가평군, `강남구` → 구=강남구, `청주시 청원구` → 시=청주시·구=청원구.

### 6.4 업체 지역 선택 및 공고 지역제한 비교

1. 업체는 SRM 지역그룹(`company.area_limit`)을 선택한 후 해당 그룹의 시·군·구(`company.sub_area_code`)를 필수 선택한다. 선택지는 `srm_region_district_master`를 사용한다. 시·군·구 코드의 앞자리 `0`을 보존한다.
2. 공고 `findRegionCodeData`의 `areaCode`와 업체 `area_limit`를 비교한다. 코드 체계 대응이 검증된 경우에만 직접 비교한다.
3. 공고 `subAreaCode`가 `null`이고 광역 지역코드만 존재하면 **광역 지역 전체 제한**으로 판정한다. 공고에 `subAreaCode`가 있으면 업체 `sub_area_code`와도 비교한다. 여러 지역 행이 있으면 전체 목록과 결합 조건을 확인한다.
4. 실제 응답 검증: `E012300731`은 `areaCode=F`, `subAreaCode=null`(강원 전체); `E012300540`은 `areaCode=F`, `subAreaCode=011008`(영월군). 두 공고 모두 `regionLimitAutoEvalMethod=Auto`이며 후자는 유찰 후 강원 전체로 확대 재공고된 사례다.
5. 지역제한이 없다는 사실을 **정상 조회 결과로 확인한 경우에만** `NOT_APPLICABLE`로 처리한다. 조회 실패, 코드 대응 불명확, 주소 검증 실패, 수동심사 또는 복수 지역 결합 규칙 불명확은 `REVIEW`로 처리한다.

### 6.5 기존 전남·광주 코드 예외

SRM 공고에서 `U(전남)` 또는 `W(광주)`가 조회되면:

- `I(전남광주)`로 **자동 변환하지 않는다.**
- 업체의 지역그룹과 무관하게 지역조건을 `REVIEW`로 판정한다.
- 사용자에게 공고 담당자 확인을 안내한다.
- 다른 조건에서 명확한 불일치가 있으면 종합 결과는 `조건 불일치`로 처리할 수 있다.

**사용자 안내 문구(기획안):**

> 해당 공고에는 기존 전남 또는 광주 지역제한 코드가 적용되어 있습니다. 2026년 7월 전남·광주 행정구역 통합에 따른 지역제한 적용 기준이 불명확하므로, 실제 입찰참가 가능 여부를 공고 담당자에게 확인하시기 바랍니다.

**검증 필요:** 위 문구의 행정구역 통합 시행일·공식 명칭은 서비스 배포 전 공식 자료로 확인한다. 이 문서는 합의된 **SRM 코드 처리 정책**을 우선 정의한다.

## 7. 참가자격 비교 및 판정

| 업체정보 | 공고정보 | 방식 |
|---|---|---|
| 일반 면허 | `licenseQualificationCode` | 코드 비교 |
| 제한경쟁입찰자격 | `qualifiedQualificationCode` | SRM 코드 + 검증된 상하위 인정 규칙 + AND/OR |
| 지역그룹 | `areaCode` | 검증된 코드 대응 비교 |
| 본점 시·군·구(`sub_area_code`) | `subAreaCode` | 세부 지역코드 비교 |
| 면허 주력분야 | `findLicenseMainCodeData` | 자동 보유 여부 비교 제외; 제한이 있으면 `REVIEW` |

| 상태 | 표시 | 의미 |
|---|---|---|
| `MATCH` | 충족 | 해당 조건 일치 |
| `MISMATCH` | 불일치 | 해당 조건 불일치 |
| `REVIEW` | 추가 확인 필요 | 불명확·조회 실패·예외 코드 |
| `NOT_APPLICABLE` | 해당 조건 없음 | 제한이 없음을 실제로 확인 |

종합 결과: **명확한 불일치가 하나라도 있으면 `조건 불일치`** → 불일치는 없지만 미확인 조건이 있으면 `추가 확인 필요` → 모든 적용 조건 충족 및 미확인 사항이 없으면 `1차 조건 충족`. 복수 자격의 AND/OR 관계가 불명확하면 충족으로 단정하지 않는다. `findBid`의 `licenseAutoEvalMethod`, `licenseAutoEvalType`, `qualifiedAutoEvalMethod`, `qualifiedAutoEvalType`, `regionLimitAutoEvalMethod`와 각 상세 조회 응답을 함께 사용한다. `Auto`인 조건만 검증된 AND/OR 규칙으로 계산하며 `Manual`은 `REVIEW` 처리한다. 주력분야는 업체 입력을 받지 않으므로 `findLicenseMainCodeData`가 정상 조회되어 **하나 이상 반환되면** 해당 항목을 `REVIEW` 처리한다. 빈 배열은 정상 조회된 경우에만 주력분야 제한 없음으로 본다. 명확한 불일치가 있는 경우 종합 `MISMATCH`가 우선한다.

## 8. 공고별 판정 결과 — `company_bid_eligibility`

| `notice_no` | VARCHAR(50) | 공고번호 |
| `license_status` | VARCHAR(20) | 면허 판정 |
| `qualification_status` | VARCHAR(20) | 제한경쟁입찰자격 판정 |
| `region_status` | VARCHAR(20) | 지역 판정 |
| `license_main_status` | VARCHAR(20) | 주력분야 판정(`REVIEW` 또는 `NOT_APPLICABLE` 등) |
| `overall_status` | VARCHAR(20) | 종합 판정 |
| `reason` | TEXT | 판정 사유 |
| `checked_at` | DATETIME | 판정일시 |

업체정보나 공고 조건 변경 시 재판정한다. 판정 사유에는 불일치 코드, 적용된 자격 상하위 인정 규칙, 지역 제한 범위, 주력분야 수동 확인 필요 여부를 남긴다. 본 결과는 SRM 구조화 조건에 대한 1차 판정이며 HWP/HWPX 공고문에만 있는 조건·공동수급·PQ·실적 등은 별도 확인 대상이다.

## 12. MVP 범위 및 미확정 사항

**MVP:** 업체 기본정보 입력·수정, 사업자등록번호 선택 입력, 본점 주소 및 SRM 지역그룹·시군구 선택, 일반 면허 복수 등록과 등록번호·등록일자, 제한경쟁입찰자격 복수 선택, 공고별 면허·자격·지역조건 1차 비교, `U/W` 예외 안내.

**후속:** 사업자 진위 확인, 업체 사용자 소속 승인, 증빙 확인, 주소 자동 분석, 실적·시공능력 및 적격심사 점수.

**추가 검증:** `areaLimit`↔`areaCode`, `code`↔`subAreaCode`의 전 지역 실제 대응, 제한경쟁입찰자격 OR 실제 공고, 상하위 인정의 최신 적용 근거, 복수 지역 결합 규칙, 행정구역 통합 시행 정보, 다중 사용자 기능의 MVP 포함 여부.

**주력분야 정책:** 업체로부터 주력분야를 입력받지 않는다. SRM `findLicenseMainCodeData`에 주력분야 제한이 존재하면 다른 자동심사 조건이 충족되어도 `추가 확인 필요`로 분류한다(단, 다른 조건에 명확한 불일치가 있으면 불일치 우선).

> **서비스 공통 안내:** 본 결과는 사용자가 등록한 업체정보를 기준으로 분석한 1차 참가자격 검토 결과이며, 실제 입찰참가 가능 여부는 공고문 및 발주기관의 기준을 확인해야 합니다.
